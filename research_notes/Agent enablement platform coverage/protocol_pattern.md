# Protocol/API access pattern for AI shopping agents: what merchants must expose, what fidelity is lost, and whether it works (as of 3 November 2026)

Scope note: "spec text" below is quoted or closely paraphrased from protocol documentation; "observed" means measured by a third party; "vendor claim" means the company's own marketing or press. All dates are stated. Where a fact could not be sourced it is listed under Gaps, not asserted.

## Key question 1: Per-protocol merchant data model — required feed/endpoint schema, update-frequency rules, mandatory vs optional fields, and whether shipping/regional eligibility is expressed before the cart exists

### Takeaway
Every major surface now runs on the same two-layer pattern: a batch product feed (Merchant Center-style, usually daily snapshot) for discovery, plus a live checkout endpoint (UCP or ACP) for price/stock truth at the moment of purchase. In every protocol the feed layer is lossy by design (variant, promo, member pricing, regional shipping and age restrictions are optional or absent), and the live layer is the only place the merchant's real price appears; shipping eligibility is generally not expressible before a checkout session is created, except coarsely via feed country targeting or a cart-eligibility flag.

### Cited Findings

**UCP (Google/Shopify Universal Commerce Protocol) — checkout, cart, catalog, order capabilities**
- Current spec version is 2026-08-25 (per URL path and `ucp.version` in examples); the checkout capability is `dev.ucp.shopping.checkout`. Required fields on a checkout resource: `ucp`, `id`, `line_items`, `totals`, `status`, `currency`, `links` (privacy policy and ToS "mandatory for legal compliance"). Optional: `buyer`, `context`, `signals`, `attribution`, `actions`, `messages`, `policies`, `expires_at`, `continue_url`, `payment`, `order`. Default `expires_at` is 6 hours from creation. (spec text, fetched 3 Nov 2026) — [ucp.dev Checkout spec](https://ucp.dev/specification/shopping/checkout/)
- Line items carry `item` (`id`, `title`, `price`, optional `quantity_unit`/`unit_price`, `image_url`), integer `quantity`, `totals[]`, and optional `parent_id` "for any nested structures". Fulfillment (shipping) is an extension and is optional "so digital goods can check out without it"; Discounts is an extension; taxes appear only as a totals type. Subscriptions and bundles are not defined; `parent_id` nesting is the only structural support. (spec text) — [ucp.dev Checkout spec](https://ucp.dev/specification/shopping/checkout/)
- Totals: "Well-known values: subtotal, items_discount, discount, fulfillment, tax, fee, total"; "Exactly one `type: "subtotal"` MUST be present" and "Exactly one `type: "total"` MUST be present"; sub-lines must sum to the parent; "Platforms MUST NOT substitute their own computed totals for the business's values." (spec text) — [ucp.dev Checkout spec (second half)](https://ucp.dev/specification/shopping/checkout/)
- UCP overview lists capabilities: Checkout (REST, MCP, A2A, Embedded transports), Cart (REST, MCP, Embedded), Order (REST, MCP), Catalog with Search and Lookup sub-pages (REST, MCP), Permalink, Ask, Identity linking, Location; extensions Fulfillment, Discounts, Buyer Consent, Loyalty; payment extensions AP2 Mandates, Payment Authentication (3DS), Payment Terms, Split Payments. Businesses "publish their profile at `/.well-known/ucp`"; `ucp.version`, `ucp.services`, `ucp.payment_handlers` are required, `ucp.capabilities` optional; the example profile includes a top-level `keys[]` of public JWKs for signing. (spec text, overview page is 211k chars; only the first 100k read) — [ucp.dev overview](https://ucp.dev/specification/overview/)
- Observed deployment: of 11,414 verified UCP stores on 7 July 2026, 11,389 declared Checkout, 10,114 Order, 10,109 Cart, 15 Identity, and 0 Payment; 99.7% ran spec version 2026-04-08. (observed, third-party crawler) — [UCP Checker, State of Agentic Commerce July 2026](https://ucpchecker.com/blog/state-of-agentic-commerce-july-2026)
- The ucp.dev AP2 mandates extension page returned HTTP 404 on 3 Nov 2026, so the UCP-side binding rules could not be read directly (see Gaps). — [ucp.dev/specification/payment/ap2-mandates/](https://ucp.dev/specification/payment/ap2-mandates/)

**Google Merchant Center requirements for UCP-powered ("agentic") checkout on AI Mode and Gemini**
- Prerequisite: "You must have a Merchant Center account in good standing and approved products for free listings in your account." Return policies must be defined in Merchant Center (shown on checkout screen; must include return cost, return window, and link to full policy; can be per-product via `returns` attribute). At least one customer support contact (URL, email, or phone) is required and "is used to generate the 'Contact Merchant' link on the order confirmation page." (spec text) — [Google UCP Merchant Center overview](https://developers.google.com/merchant/ucp/guides/overview/merchant-center)
- Product data: `native_commerce(checkout_eligibility)` is a boolean; "set to `FALSE` or missing, the product won't be eligible for checkout." Cart eligibility is opt-out (`cart_eligibility` FALSE excludes) once `dev.ucp.shopping.cart` is declared in the UCP profile. Composite format `checkout_eligibility:cart_eligibility` (e.g. `FALSE:TRUE`); the `native_commerce` group is fully overwritten on each upload. Consumer notices (`notice_type` = `legal_disclaimer`, `safety_warning`, `prop_65`; `notice_message` max 1000 chars) are required for items with regulatory warnings and are displayed on the Checkout screen. `merchant_item_id` maps the Merchant Center `id` to the ID the merchant's Checkout API expects and "takes precedence in Agentic requests". `variant_option` (up to 30 per item, 250-char name/value) plus `item_group_id`/`item_group_title` are "strongly recommended" for multi-variant items. Submission is via supplemental feed or Merchant API custom attributes; the Content API is deprecated and `products.update` does not support `customAttributes`. (spec text) — [Google UCP Merchant Center overview](https://developers.google.com/merchant/ucp/guides/overview/merchant-center)
- Ineligible for checkout (must set `checkout_eligibility` FALSE/empty): subscriptions, installments, personalized goods, non-new or final-sale items, pre-orders, bundled services, special shipping, gifting, in-store activation, age-restricted items, prohibited content, services (except Travel rails), rentals, virtual items, goods requiring software installation. (spec text) — [Google UCP Merchant Center overview](https://developers.google.com/merchant/ucp/guides/overview/merchant-center)
- Freshness: "Use the Merchant API to keep pricing, availability, and product details synchronized in real time"; if using scheduled feeds, "send supplemental price and availability updates through the Merchant API or Content API to avoid checkout price mismatches." The page states no numeric freshness interval and no rule about what happens if checkout price exceeds feed price. (spec text) — [Google UCP Merchant Center overview](https://developers.google.com/merchant/ucp/guides/overview/merchant-center)
- Scope: "Only product listings using the `native_commerce(checkout_eligibility)` product attribute display the Buy now button"; checkout "is available for select merchants" in an early access program; "this applies only to products sold within the United States"; the UCP integration hub is "gradually rolling out in the United States" with Australia and Canada "expected early next year"; merchants without hub access use the Direct API path. Sandbox and production endpoint validation covers create checkout, update shipping settings, complete transaction, and cart transfer. (spec text) — [Google UCP Merchant Center tools](https://developers.google.com/merchant/ucp/guides/tools/merchant-center)
- Help-center page: applies to products eligible in US, Canada and Australia; "You will remain the seller of record"; currently uses "standard Funding Primary Account Numbers (FPANs)" stored in Google Wallet; merchants need a Google Pay & Wallet Console account; interest form at support.google.com/merchants/contact/ucp_integration_interest. — [Google Merchant Center help 16837055](https://support.google.com/merchants/answer/16837055?hl=en)
- Google's broader Merchant Center feed rule: "Automations may not work for products with frequent price or availability value changes" and "The product may be disapproved instead of updated if we detect a mismatch"; automations are enabled by default, apply to price, sale price, availability, condition, work "for a small percentage of your products", and "We may also stop updates if the total number of detected mismatches becomes too large." (spec text, help page as of 3 Nov 2026) — [Google Merchant Center help 12157888](https://support.google.com/merchants/answer/12157888?hl=en). A secondary report dates the "more than once a day" disapproval warning to a 27 Sept 2026 documentation revision, reported 8 Oct 2026; it was a documentation edit, not a product launch, and the exact wording should be confirmed on Google's page. — [Relevant Audience](https://www.relevantaudience.com/ecommerce-marketing/merchant-center-automatic-item-updates-disapproval-warning/)
- Google price-mismatch policy (non-agentic baseline): prices at checkout must match landing page; extra checkout fees must be built into price or shipping; checkout price above landing-page price earns a 28-day warning; feed/landing mismatch can disapprove the product. — [Google Merchant Center help 10330822](https://support.google.com/merchants/answer/10330822); [help 12159029](https://support.google.com/merchants/answer/12159029?hl=en)

**Google "Agentic checkout with Google Pay" (the non-UCP, agent-on-merchant-site path, launched 13 Nov 2025)**
- Purchases proceed only if the final price is "the same as, or lower than the total price you confirmed"; "If the price goes up, the purchase doesn't go through and you aren't charged." Failure notifications cover out-of-stock, "the price changes significantly between the time you confirm" and purchase, or card expired/declined. Works at "select merchants that accept Google Pay"; "only available in the US and Australia" in English; buyer contacts the merchant for wrong items, cancellations, returns. (spec text, help page) — [Google Pay help 16421147](https://support.google.com/googlepay/answer/16421147?hl=en)
- Target prices apply to item price only; "shipping and tax costs are not part of price tracking and will be added on top"; "Agentic checkout doesn't support promo codes or loyalty rewards." (help text via search summary) — [Google Pay help 16421147](https://support.google.com/googlepay/answer/16421147); launch context — [Google blog, Nov 2025](https://blog.google/products/shopping/agentic-checkout-holiday-ai-shopping/); [Digital Commerce 360, 13 Nov 2025](https://www.digitalcommerce360.com/2025/11/13/google-debuts-agentic-checkout-and-ai-mode-shopping-features-for-the-holidays/)

**ACP (OpenAI Agentic Commerce Protocol) — product feed spec and Agentic Checkout spec**
- Feed, required for discovery (9 fields): `item_id`, `title`, `description`, `url`, `brand`, `seller_name`, `image_url`, `availability` (`in_stock`, `out_of_stock`, `pre_order`, `backorder`, `unknown`; omitted/unknown values reject the row), `price` (string, e.g. `79.99 USD`). Optional: `is_eligible_search` (default true), `is_ads_eligible`, `is_eligible_checkout`; `sale_price` (must be below `price`), `shipping_price`, `shipping` (tuple "requires feed-specific setup"); returns `accepts_returns`, `return_deadline_in_days`, `return_policy`, `accepts_exchanges`; variants `group_id`, `listing_has_variations`, `variant_dict`, `offer_id`, `gtin`, `mpn`; attributes `condition`, `product_category`, `material`, `color`, `size`, `size_system`, `gender`, `age_group`, dimensions/weight; reviews; `seller_url`, `marketplace_seller`, `store_country`; `seller_privacy_policy`, `seller_tos` (conditional for checkout); `is_digital`, `target_countries`. Notable rules: "This is a product attribute, not a purchase-age restriction" (on `age_group`); "A policy URL does not set or override this field" (returns); "Checkout requires a separately enabled integration." `inventory_quantity`, `geo_price`, `geo_availability`, bundles and subscriptions do not appear in the read portion. Markets: "The standard OpenAI-format upload currently targets the US"; shared format represents US, CA, MX. (spec text, developers.openai.com llms-full.txt, read 3 Nov 2026) — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt)
- Newer products schema (same doc, first half): Product requires `id` and `variants`; Variant requires `id` and `title`; `price`, `availability`, `variant_options`, `seller`, `condition`, `categories` optional at variant level; guidance to keep `title`, `url`, `description`, `media`, `availability`, `price` variant-specific. Delivery: SFTP push in Parquet (zstd preferred), `jsonl.gz`, `csv.gz`, `tsv.gz`; shards up to ~500k items/<500 MB; "We recommend uploading a full snapshot at least once a day"; "A product is not deleted immediately when missing from a processed snapshot" (retained record expires within 14 days). Feed onboarding "is currently available to approved partners" via chatgpt.com/merchants. (spec text) — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt)
- Promotions API: `GET/PATCH /product_feeds/{id}/promotions`; required `id`, `title`, `active_period`, `benefits`; benefit types `amount_off`, `percent_off`, `free_shipping`. (spec text) — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt)
- Checkout spec endpoints: `POST /checkout_sessions`, `POST /checkout_sessions/{id}`, `POST /checkout_sessions/{id}/complete`, `POST /checkout_sessions/{id}/cancel` (405 if not cancelable), `GET /checkout_sessions/{id}`. Status enum: `not_ready_for_payment`, `ready_for_payment`, `completed`, `canceled` (`in_progress` appears only in an example, an internal inconsistency). Message error codes: `missing`, `invalid`, `out_of_stock`, `payment_declined`, `requires_sign_in`, `requires_3ds`; no "price changed" code. (spec text) — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt)
- One secondary source reports OpenAI accepting feed updates "every 15 minutes"; this is not in the OpenAI doc text read and is unverified. — [Productsup, via search](https://www.productsup.com/agentic-commerce)

**AP2 (Google Agent Payments Protocol)**
- The current site uses "Checkout Mandate" and "Payment Mandate" (v0.2 renamed what earlier explainers call Intent/Cart Mandates); each has an Open stage ("Captures the user's constraints and goals") and a Closed stage ("Captures the user's (or agent's) authorization for a specific, finalized checkout"); the Closed Payment Mandate "Captures the authorization for a specific transaction amount bound to a finalized checkout." AP2 is "an extension for the open-source Agent2Agent (A2A) protocol and Universal Commerce Protocol" and was donated to the FIDO Alliance (announcement dated 16 Sept 2025; "AP2 v0.2 Release and FIDO Alliance Donation" link). — [ap2-protocol.org](https://ap2-protocol.org/)
- Checkout Mandate spec: Open mandate (`vct` = `mandate.checkout.open.1`) carries constraints `checkout.line_items` and `checkout.allowed_merchants`, a `cnf` holder key, `iat`, `exp`. Closed mandate (`vct` = `mandate.checkout.1`) carries `checkout_jwt` (selectively disclosable) and `checkout_hash` (not selectively disclosable). The Merchant "verifies the content and creates a signed Checkout object, which becomes `checkout_jwt`" (example header `ES256`); "when used with the Universal Commerce Protocol this MUST be the Checkout object." Example payload includes `line_items` (id, title, price, currency, quantity), `total_price`, `currency`, `merchant` (id, name, website), `order_id`, `shipping_policy`, `return_policy`; `iat`/`exp` one hour apart in the example. Merchant verification rules: "The Merchant MUST be present in the revealed elements of `allowed`"; "No `items` entry or item in the Checkout may be used more than once"; splitting an open mandate across multiple checkouts is not allowed ("consideration must be given to how multiple duplicate orders can be prevented"). Checkout Receipt `reference` is "the hash of the closed Mandate that this receipt is binding to." The page does not describe price-change handling, user signature role, or human-not-present rules. (spec text, read 3 Nov 2026) — [AP2 Checkout Mandate](https://ap2-protocol.org/ap2/checkout_mandate/)
- Third-party descriptions disagree on who signs the Cart Mandate (merchant vs user vs both); the official page above indicates the merchant signs the Checkout object and an agent-provider key (`kid: "agent-provider-key-1"`) signs the outer SD-JWT. Treat explainer-blog claims of "user signs cart mandate" as pre-v0.2 descriptions. — [Stellagent AP2 explainer](https://stellagent.ai/insights/ap2-agent-payments-protocol); [Descope AP2](https://www.descope.com/learn/post/ap2)

### Inferences
- Fidelity loss by field, inferred from the schemas above: (a) variant-level attributes are optional in both ACP (`variant_dict`, `variant_options`) and Google (`variant_option` "strongly recommended") so agents routinely see parent-level data; (b) real-time availability is only an enum (`in_stock`, etc.) in feeds with no quantity, and Google itself tells merchants to push Merchant API updates to "avoid checkout price mismatches", i.e., the feed is expected to be stale; (c) taxes and shipping are never in the feed as a final number (ACP has `shipping_price`; Google Pay agentic checkout explicitly adds shipping/tax on top of the tracked price); (d) promotions exist as separate objects (ACP Promotions API) and Google Pay agentic checkout "doesn't support promo codes or loyalty rewards"; member/loyalty pricing only surfaces via UCP's Loyalty extension or identity linking, which 15 of 11,414 verified UCP stores declared in July 2026; (e) regional eligibility pre-cart is limited to `target_countries`/`store_country` (ACP) and Merchant Center country targeting; true deliverability appears only as a UCP `address_undeliverable` error after a session exists; (f) age/licence restrictions are handled by exclusion (Google: age-restricted items must be `checkout_eligibility` FALSE; ACP: `age_group` "is not a purchase-age restriction"); (g) bundles and subscriptions are excluded from Google UCP checkout and Meta direct checkout and are undefined in UCP/ACP schemas.
- Because UCP Checkout is a live endpoint computed by the business ("Platforms MUST NOT substitute their own computed totals"), the merchant's truth is preserved at checkout time; the loss is concentrated in the discovery/feed layer, which is what the agent reasons over before it ever calls the endpoint.

### Gaps
- UCP's AP2 Mandates extension page (ucp.dev/specification/payment/ap2-mandates/) returned 404; the exact UCP-side hash/signature binding could not be quoted.
- Meta's own Commerce Manager documentation for Muse catalog or checkout flags was not found; everything above is Shopify-channel documentation reported second-hand.
- Perplexity's official merchant documentation was not retrieved; feed schema and fee terms are secondary.
- Microsoft Merchant Center help-center field-level UCP feed documentation was not found; only the marketing page's attribute list.
- OpenAI's `geo_price`/`geo_availability`, `inventory_quantity`, and any numeric update-frequency limit were not in the portions of the docs read (148k chars; both halves were read but the field table is split across them).
- Visa TAP merchant specification detail (signature fields, key discovery, agent registry) was not retrieved; only the overview.

## Key question 2: Mismatch handling, seller of record, evidence the merchant receives, and whether the merchant can inject a "needs human approval" step

### Takeaway
All protocols keep the merchant as seller/merchant of record and make the merchant's live response authoritative; UCP is the only one with a spec-level "human in the loop" primitive (`requires_escalation` plus `requires_buyer_review` messages and `continue_url`), ACP has only `not_ready_for_payment` and a `manual_review` order status after the fact, Google Pay agentic checkout enforces a hard price ceiling on the buyer side, and AP2 binds the merchant-signed checkout hash so any change invalidates the mandate.

### Cited Findings
- UCP statuses: `incomplete` ("missing required information or has issues that need resolution"), `requires_escalation` ("requires information that cannot be provided via API, or buyer input is required"), `ready_for_complete`, `complete_in_progress` ("the Business is processing the order"; response must not contain `order`), `completed` ("Order placed successfully"), `canceled` ("invalid or expired"). `continue_url` is required when status is `requires_escalation`, must be absolute HTTPS. (spec text) — [ucp.dev Checkout spec](https://ucp.dev/specification/shopping/checkout/)
- UCP message severities: `recoverable` (platform fixes input and resubmits), `requires_buyer_input` (business needs data its API cannot collect; hand off via `continue_url`), `requires_buyer_review` ("policy, regulatory, or entitlement rules require buyer authorization before order placement"; checkout otherwise complete; hand off via `continue_url`), `unrecoverable`. Warnings may carry `presentation: disclosure`, which "must stay near their `path` target and must not be hidden or auto-dismissed"; platforms that cannot render a disclosure must escalate to the merchant UI. Standard error codes: `out_of_stock`, `item_unavailable`, `address_undeliverable`, `payment_failed`, `eligibility_invalid`. (spec text) — [ucp.dev Checkout spec](https://ucp.dev/specification/shopping/checkout/)
- UCP mismatch rule: "platforms MUST NOT autonomously complete a checkout with mismatched totals"; they "SHOULD reject the checkout or escalate and ask for buyer review via `continue_url`." Quantity revisions: business response is authoritative; "Silent conversion is forbidden in both directions." Update Checkout is a full replacement; updates during `complete_in_progress` are rejected with a recoverable error; "Unresolved eligibility claims must block completion." After `completed` the checkout is immutable; the business "MUST send a confirmation email"; `order` carries `id` and `permalink_url` (required) and optional `label`. Idempotency: a new Complete after returning to `ready_for_complete` "must use a fresh idempotency key." The business "remains the Merchant of Record (MoR)". Finalization "requires a trusted UI unless the AP2 Mandates extension is supported." (spec text) — [ucp.dev Checkout spec](https://ucp.dev/specification/shopping/checkout/)
- ACP: "OpenAI is not the merchant of record in the Agentic Commerce Protocol"; merchants handle refunds and chargebacks and send `ORDER_UPDATE` webhooks; webhook events `order_created`/`order_updated` carry an HMAC `Merchant_Name-Signature` header; order statuses `created`, `manual_review`, `confirmed`, `canceled`, `shipped`, `fulfilled`. Delegated payment: OpenAI sends a one-time allowance (`max_amount`, `expires_at`), PSP returns a token forwarded on complete; Stripe Shared Payment Token is "the first Delegated Payment Spec-compatible implementation"; direct integration limited to PSPs or PCI DSS Level 1 merchants. Session statuses `not_ready_for_payment`/`ready_for_payment`; error codes include `out_of_stock`, `requires_sign_in`, `requires_3ds`; there is no price-changed code. (spec text) — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt)
- Google Pay agentic checkout (agent on merchant site): buys only if final price is "the same as, or lower than the total price you confirmed"; otherwise "the purchase doesn't go through and you aren't charged"; buyer is notified if out of stock or "the price changes significantly." Merchant evidence is an ordinary order placed on its site; the buyer is directed to "contact the merchant" for returns/cancellations. (spec text) — [Google Pay help 16421147](https://support.google.com/googlepay/answer/16421147?hl=en)
- Google UCP checkout: merchant "will remain the seller of record"; Merchant Center performance reporting (alpha) exposes `buy_button_clicks`, `accounts_linked`, `account_linking_rate`, `purchase_count`, `cancellations`, `cart_transfers`, `purchase_value`, `average_order_value` by `date`, `account_id`, `customer_country_code`, and per-`offer_id`; "This feature is in alpha (experimental) and is subject to change." — [Google Merchant API UCP performance reports](https://developers.google.com/merchant/api/guides/reports/ucp-performance-reports); [Google help 16837055](https://support.google.com/merchants/answer/16837055?hl=en)
- AP2: merchant signs the Checkout object (`checkout_jwt`); `checkout_hash` uniquely identifies the checkout; merchant must verify it appears in `allowed` merchants and that line items satisfy the open-mandate constraints with no reuse; the Checkout Receipt binds to "the hash of the closed Mandate." No explicit price-change rule, but since the hash is over the merchant-signed checkout, a changed total yields a different hash. (spec text) — [AP2 Checkout Mandate](https://ap2-protocol.org/ap2/checkout_mandate/)
- Microsoft: "You are the merchant of record. Copilot does not become merchant of record." — [Microsoft agentic commerce page](https://about.ads.microsoft.com/en/solutions/technology/agentic-commerce)
- Meta/Shopify: "Orders are attributed to Meta, and the merchant stays the merchant of record." (secondary) — [Vaizle](https://insights.vaizle.com/news/shopify-adds-meta-as-an-ai-commerce-channel-in-agentic-storefronts)
- Amazon Buy for Me: brand sends the order confirmation, handles fulfilment, returns, support; Amazon "does not currently take a cut." — [Marketing4ecommerce](https://marketing4ecommerce.net/en/how-buy-for-me-works-the-amazon-newest-feature/); [About Amazon](https://www.aboutamazon.com/news/retail/amazon-shopping-app-buy-for-me-brands)
- Card networks: Mastercard says "Standard fraud detection, chargeback rights, and dispute resolution processes apply to agentic transactions"; Amex offers cardmember (not merchant) coverage for registered-agent errors. — [Mastercard Developers L1 guide](https://developer.mastercard.com/merchant-cloud/documentation/tutorials-and-guides/agentic-commerce-guide/21/)
- Forter (observed, 2 Nov 2026): merchant cancellation of human orders ~10%; ChatGPT and Instinct orders are cancelled by merchants most often, OpenAI (protocol) orders least; scraping-agent orders outside North America are cancelled at 27% (Asia/Middle East) and 37% (Europe). — [Forter, AI Agent Order Data](https://www.forter.com/blog/ai-agent-order-data/)

### Inferences
- A merchant can inject a human-approval step with real UI only under UCP: respond `requires_escalation` with a `requires_buyer_review` message and a `continue_url` to its own page; the platform is required to hand off. Under ACP the equivalent is to hold the session in `not_ready_for_payment` with a `requires_sign_in` message (sends the buyer to the merchant) or accept the order and mark it `manual_review` after the fact. Under screen-scraping agents (Muse, ChatGPT Agent, Grok Bot, Instinct) the only lever is the merchant's own checkout page and bot controls.
- Evidence quality ranks: AP2-with-UCP (merchant-signed checkout hash plus receipt) > UCP (`order.id`, `permalink_url`, platform profile URI per request, signatures spec) > ACP (HMAC-signed webhooks, order IDs, PSP token with `max_amount`) > Google Pay agentic checkout and Amazon Buy for Me (ordinary order; the agent is identifiable only by email domain such as @buyforme.amazon).

### Gaps
- No protocol document read states numerically how large a price delta is tolerated; Google Pay's "changes significantly" is undefined.
- Whether Google's UCP checkout rejects a checkout whose live total exceeds the Merchant Center price (a "price ceiling" rule) is not stated on the pages read; Google only advises Merchant API syncing "to avoid checkout price mismatches."
- ACP docs do not say what ChatGPT does when the feed price and session price differ.

## Key question 5: What a small merchant on WooCommerce, Wix, Magento, or a custom cart must do today to be buyable through ChatGPT, Google AI Mode, Copilot, Muse, and Perplexity, and where it breaks

### Takeaway
Outside Shopify, the realistic path on 3 Nov 2026 is: (1) a Google-format feed in Google Merchant Center and Microsoft Merchant Center plus an OpenAI/Stripe/PayPal catalog for discovery, (2) a `/.well-known/ucp` profile with checkout/cart endpoints via a platform plugin or self-build, and (3) a PSP route (Stripe or PayPal) for checkout in ChatGPT, Copilot and Perplexity; it breaks at eligibility gates (US-only, "select merchants", waitlists), at variant/ID mapping, and at the fact that Muse and ChatGPT Agent will simply drive the merchant's web checkout regardless.

### Cited Findings
- Google AI Mode/Gemini: Merchant Center account in good standing with approved free listings; return policy and support contact set; `native_commerce(checkout_eligibility)` and `merchant_item_id` attributes; UCP endpoints validated in the Merchant Center sandbox; interest form; "select merchants" early access, US products only; merchants on third-party platforms "should contact that provider about its UCP plans." Without the Buy button, products still appear in AI Mode as click-out listings. — [Google UCP Merchant Center overview](https://developers.google.com/merchant/ucp/guides/overview/merchant-center); [Google tools page](https://developers.google.com/merchant/ucp/guides/tools/merchant-center); [ClearAds note on native_commerce](https://clearadsagency.com/the-hidden-google-setting-that-controls-whether-ai-buys-your-products/)
- ChatGPT: apply at chatgpt.com/merchants; feed onboarding "currently available to approved partners"; full daily snapshot over SFTP; checkout "requires a separately enabled integration" and, since March 2026, is delivered via the merchant's own checkout or a ChatGPT App; Stripe's suite (waitlist, Stripe-as-PSP) or PayPal Store Sync are the practical routes; standard upload "targets the US." — [OpenAI commerce docs llms-full](https://developers.openai.com/commerce/llms-full.txt); [CNBC, 24 Mar 2026](https://www.cnbc.com/2026/03/24/openai-revamps-shopping-experience-in-chatgpt-after-instant-checkout.html); [Stripe docs](https://docs.stripe.com/agentic-commerce/enable-in-context-selling-on-ai-agents)
- Copilot: MMC account plus UCP-ready feed (GA in US since April 2026) for discovery; Copilot Checkout via PayPal/Stripe application or MMC pilot; English/US/USD only; one PSP partner per merchant. — [Microsoft agentic commerce page](https://about.ads.microsoft.com/en/solutions/technology/agentic-commerce); [Microsoft April 2026 blog](https://about.ads.microsoft.com/en/blog/post/april-2026/win-across-all-three-eras-of-the-web)
- Muse: no documented non-Shopify merchant program; PayPal merchants reportedly can check out in Muse; otherwise Muse scrapes and drives the merchant's web checkout (Forter), and the only control is the merchant's bot policy. — [Forter, AI Agent Order Data](https://www.forter.com/blog/ai-agent-order-data/); [Stellagent Muse](https://stellagent.ai/insights/meta-muse-shop-pay-paypal-agentic-checkout)
- Perplexity: merchant program application (must ship to US); CSV feed in Google format; in-chat checkout via Firmly/PayPal; non-program merchants get click-out links. — [Alhena guide](https://alhena.ai/blog/perplexity-shopping-merchants-setup-guide/); [WebsiteBuilderExpert](https://www.websitebuilderexpert.com/news/perplexity-merchant-program/)
- Platform specifics: WooCommerce "Enable agentic commerce" toggle plus community UCP plugins; Wix UCP via wixapis.com and App Market adapters plus Stripe module; Magento/Adobe via third-party modules pending native support; custom carts build UCP themselves (7% verified in May 2026, 356 ms avg manifest latency for those that did). — [WooCommerce docs](https://woocommerce.com/?p=18734006949860); [UCP Checker Wix](https://ucpchecker.com/platforms/wix); [Kinex Media, Adobe](https://www.kinexmedia.com/blog/ucp-on-adobe-commerce/); [UCP Checker May 2026](https://ucpchecker.com/blog/state-of-agentic-commerce-may-2026)
- Card-network baseline for any merchant: keep server-rendered product/checkout HTML, accept network tokens, verify Web Bot Auth signatures, do not decline solely on 3DS failure. — [Mastercard L1 guide](https://developer.mastercard.com/merchant-cloud/documentation/tutorials-and-guides/agentic-commerce-guide/21/)

### Inferences
- Step order that minimizes rework for a non-Shopify small merchant: (1) fix one canonical Google-format feed with variant IDs, GTIN/brand, return policy, and daily (or Merchant API) updates, since Google, Microsoft, Perplexity, and Stripe/PayPal all accept or derive from it; (2) publish a UCP profile via plugin, which also serves Shopify-style MCP catalog tools on Wix/WooCommerce; (3) apply to Stripe or PayPal agentic programs for ChatGPT/Copilot/Perplexity checkout; (4) submit Google's UCP interest form and set `native_commerce`; (5) harden the web checkout for scraping agents (Muse, ChatGPT Agent), which will arrive regardless.
- Break points, by evidence: eligibility gates (every checkout program is "select merchants", US, often USD); variant and ID mismatch (UCP Checker's top failure; Google's `merchant_item_id` exists precisely because feed IDs differ from checkout IDs); feed staleness causing disapproval or checkout mismatch (Google's once-a-day automation warning); regional cancellations (27–37% merchant cancellation of scraping-agent orders outside North America per Forter).

### Gaps
- No step-by-step official guide exists from OpenAI, Microsoft, Meta, or Perplexity for non-platform small merchants; the sequence above is inferred from eligibility pages.
- Time and cost to complete a custom UCP build were not found in any source.
